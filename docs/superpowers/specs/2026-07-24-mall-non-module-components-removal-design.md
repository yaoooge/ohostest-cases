# Mall 非 `module_*` 组件剥离设计

## 目标

从 `CaseComprehensiveMallTemplate/components/` 中删除所有目录名不以
`module_` 开头的组件，同时保留商城浏览、加购、下单和订单流转主流程。
对登录、支付和地址等主流程依赖提供最小内置兜底；其余次要能力及入口直接移除。

## 删除范围

删除以下 10 个组件目录：

| 组件 | 原功能 | 删除后的处理 |
| --- | --- | --- |
| `address_management` | 地址列表、地址选择、地址编辑 | 订单与积分兑换使用现有 ViewModel 中的默认地址；移除地址管理和地址编辑入口 |
| `aggregated_login` | 华为、微信、验证码聚合登录 | 应用使用现有模拟用户作为默认已登录用户；移除登录页和登录入口 |
| `aggregated_payment` | 收银台、支付渠道和支付回调 | 提交订单或立即支付时直接执行支付成功后的订单状态更新 |
| `aggregated_share` | 商品分享和应用分享服务 | 移除分享按钮、分享面板及初始化逻辑 |
| `app_setting` | 通用应用设置界面 | 移除相应设置入口和依赖该组件的设置页面 |
| `collect_personal_info` | 个人资料采集和编辑 | 移除编辑资料入口及页面 |
| `coupons` | 优惠券查看和订单选券 | 移除优惠券入口；订单价格明细仍显示已有折扣，但不可重新选券 |
| `feedback` | 反馈提交和反馈历史 | 移除反馈入口和路由 |
| `image_preview` | 图片大图预览 | 评价图片保留普通展示，取消点击预览 |
| `membership` | 会员状态、订阅和商品模型 | 移除会员入口和订阅流程；商城不再查询会员购买状态 |

`components/module_*` 目录全部保留。若保留的 `module_*` 组件依赖上述被删除组件，
则在消费位置移除对应交互，不创建同名兼容壳。

## 改造策略

采用“精确剥离 + 主流程内联兜底”：

1. 从根 `build-profile.json5` 删除 10 个组件的模块注册。
2. 从产品、feature 和保留组件的 `oh-package.json5` 删除对应本地依赖。
3. 删除所有对这些组件的 ArkTS 导入、路由映射、生命周期注册及页面入口。
4. 仅在现有 product/feature/ViewModel 中实现必要兜底，不新增可复用组件包。
5. 不改造本次任务无关的业务架构，不剥离 `module_*` 组件，也不在本阶段删除多端适配能力。

不采用同名空壳方案，因为空壳会让组件仍作为模块存在，无法达到真实剥离目的。
不采用连同消费 feature 整体删除的方案，因为这会破坏订单和商品等核心页面。

## 主流程行为

### 登录

应用启动时保证全局用户状态使用工程已有模拟用户数据，并处于已登录状态。
登录页面、登录按钮及第三方登录 SDK 交互全部移除。需要用户信息的购物车、
订单和积分接口继续读取现有全局模拟用户。

### 支付

下单提交和待付款订单的“立即支付”不再打开收银台。触发操作后直接调用现有
订单更新逻辑，按照配送方式进入待发货或待取件状态，并保持原有成功提示和页面跳转。
支付组件的回调注册、注销和支付渠道类型全部移除。

### 地址

快递订单和积分兑换继续使用现有 ViewModel 初始化的默认收件人、电话和地址。
地址区域不再可点击跳转。地址管理、地址选择和地址编辑入口移除。

### 其他组件

- 优惠券：保留服务端返回的折扣展示，移除选择器与优惠券管理入口。
- 分享：移除商品分享入口和 Ability 中的分享服务注册。
- 应用设置、反馈、会员、编辑资料：从个人中心或设置列表直接移除入口。
- 图片预览：保留评价缩略图，移除点击大图预览行为。

## 多端适配盘点

本次只形成盘点文档，不修改多端适配代码。盘点覆盖：

- `BreakpointSystem`、断点枚举、断点存储与断点监听；
- `GridRow` / `GridCol` 的响应式断点；
- `windowSizeChange`、窗口宽高和横竖屏相关逻辑；
- 分屏导航、第二 Ability 与跨窗口路由状态；
- 平板、折叠屏及不同设备类型下的布局分支；
- `module.json5` 中的 `deviceTypes` 声明；
- 截图或 README 中仅用于说明多端支持的材料。

盘点文档按“能力类别、功能、文件、关键符号或代码位置、后续剥离影响”记录，
并区分运行时代码、配置声明、测试和说明材料。

## 测试与验证

1. 先添加静态守卫测试，验证根构建配置、包依赖和 ArkTS 源码不再引用被删除组件；
   在业务修改前运行并确认测试因现有引用而失败。
2. 为可被独立验证的默认登录、支付成功和默认地址行为添加最小测试或静态断言；
   若现有 ArkTS 测试框架无法隔离这些行为，则以对应业务 API 调用和状态更新的
   源码守卫配合完整 Hvigor 编译验证。
3. 修改后运行静态守卫、现有测试和完整 Hvigor 编译。
4. 运行残留扫描，确认 10 个目录、模块注册、包依赖和 import 均已清除。
5. 人工核对删除清单与多端适配盘点中的文件统计和实际仓库一致。

## 非目标

- 不删除或改名任何 `module_*` 组件。
- 不在本次任务中剥离断点、分屏、折叠屏或其他多端适配实现。
- 不保留被删除组件的同名模块或兼容壳。
- 不修改与 `CaseComprehensiveMallTemplate` 无关的工程和现有工作区改动。
