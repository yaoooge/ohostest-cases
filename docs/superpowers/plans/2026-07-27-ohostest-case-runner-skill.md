# OhosTest Case Runner Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a project-level Codex skill that chooses case or matrix mode for the local HarmonyOS ohosTest runner and verifies results from generated reports.

**Architecture:** Keep selection rules and the mandatory workflow in `SKILL.md`. Put detailed commands, option boundaries, report locations, and diagnostics in one directly linked reference file so only the chosen mode needs to be loaded.

**Tech Stack:** Codex Skills, Markdown, YAML, Python skill-creator utilities, npm scripts

### Task 2: Write the Skill

- [ ] **Step 1: Replace `SKILL.md`**

Use frontmatter:

```yaml
---
name: ohostest-case-runner
description: Run and diagnose HarmonyOS ohosTest validation with the local harmonyos-ohostest-runner, selecting matrix mode for direct project and focused suite validation or case mode for metadata, test_patch/golden_patch, Answer/SWE, and final case classification workflows. Use when the user asks to run case-runner, ohostest:matrix, ohostest:case, validate answer or swe, test specific devices or suites, inspect runner reports, or diagnose runner failures.
---
```

The body must:

1. Resolve absolute runner and target paths.
2. Obey explicit mode selection.
3. Select matrix for materialized projects, focused suites, or iterative Answer development.
4. Select case for metadata/patch composition, Answer/SWE/all, and classification.
5. Let the runner own emulator lifecycle by default.
6. Inspect `summary.md` and device logs instead of trusting exit code or
   `status: completed`.
7. Link directly to `references/modes.md`.
