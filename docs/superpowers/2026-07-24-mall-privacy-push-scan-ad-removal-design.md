# Mall 隐私协议、Push、扫码与广告能力剥离设计

## 背景

`CaseComprehensiveMallTemplate` 已完成非 `module_*` 组件剥离，并通过默认登录、默认支付成功和默认地址等方式保持商城主流程可用。本次继续移除以下能力：

1. 首次启动隐私协议确认页面
2. Push 能力
3. 扫码能力
4. 广告能力

本次采用物理删除方案，不保留隐藏入口、空壳模块或无调用的能力实现。

## 目标

- 普通启动不再展示隐私协议或开屏广告，直接进入 `MainEntry`。
- 商品深链、分屏商品详情和订单桌面快捷入口保持原有行为。
- 工程不再编译、依赖或调用隐私协议、Push、扫码和广告能力。
- 首页、启动路由、桌面快捷入口及文档中不再出现上述能力。
- 商城浏览、搜索、购物车、订单、默认登录和默认支付成功等主流程保持可用。

## 非目标

- 不移除通用权限申请工具，只删除其中仅服务于 Push 的通知授权逻辑。
- 不移除商品搜索能力；只删除扫码结果和扫码图片识别对商品搜索的入口。
- 不修改现有多端断点、分屏窗口和深链商品详情能力。
- 不处理 `CaseComprehensiveMallTemplate` 之外的工程。

## 方案选择

### 方案一：仅隐藏入口

保留模块、路由和底层实现，只隐藏页面按钮。改动较小，但能力依赖仍会被编译和打包，不满足“直接移除”。

### 方案二：物理删除（采用）

删除模块目录、入口、路由、配置、资源和底层实现，并通过测试约束能力不得回流。剥离完整，后续依赖和包体边界清晰。

### 方案三：保留空壳模块

保留同名模块并提供空实现，调用方改为无操作。兼容旧引用，但会留下无意义模块和维护负担，不符合当前目标。

## 详细设计

### 启动流程

- 删除 `SafePage` 和 `SplashPage`。
- 删除 `SAFE_PAGE`、`SPLASH_PAGE` 路由常量及入口模块路由注册。
- `Index` 在普通启动时直接压入 `MAIN_ENTRY`。
- `SecondAbility` 继续复制主窗口路由栈。
- 带分屏商品参数时继续直达商品详情。
- AppLinking 商品深链继续由 `SetupUtil` 解析并在主入口加载后跳转。

### 隐私协议能力

- 删除 `components/module_privacy_agreement`。
- 删除根工程模块注册和 `entry` 的本地依赖。
- 删除隐私协议页面、预览路由、偏好记录和隐私声明静态资源。

### 广告能力

- 删除 `components/module_advertisement`。
- 删除根工程模块注册和 `entry` 的本地依赖。
- 删除开屏广告页面及 OAID、广告资源等随模块实现。

### Push 能力

- 删除 `lib_foundation` 中的 `PushUtil`、Push 数据模型及导出。
- 删除 `EntryAbility` 启动阶段的 Push token 获取。
- 删除首页数据加载后的通知授权与模拟 Push 请求。
- 从 `PermissionUtil` 删除通知管理器依赖和通知授权方法，保留通用运行时权限申请能力。
- 清理 README 中 Push 服务开通与调试说明。

### 扫码能力

- 删除 `components/module_product_scan`。
- 删除根工程模块注册和 `entry` 的本地依赖。
- 删除首页搜索栏右侧扫码按钮及 `HomePageVM.jumpToScanPage`。
- 删除仅服务于扫码图片结果的文件读取、像素图转换和主体分割逻辑。
- 删除扫码桌面快捷入口、扫码快捷入口文案和图标资源。
- 删除 `SetupUtil` 对 `ScanPage` 快捷参数和扫码路由的处理。
- 保留订单桌面快捷入口。
- 从 AppScope 组件标识列表和 README 中删除扫码组件记录。

### 依赖与锁文件

- 更新根 `build-profile.json5` 和 `products/entry/oh-package.json5`。
- 通过工程依赖安装或构建流程刷新 `oh-package-lock.json5`，确认不存在被删除模块的文件依赖。
- 删除因上述能力不再使用而变成孤立的 import、资源和配置项。

### 文档

- 更新 `docs/non-module-components-removal.md`，新增本轮额外能力剥离记录，明确这三项虽以 `module_*` 命名但由后续需求删除。
- 更新 `docs/multi-device-adaptation-inventory.md`，记录扫码入口和启动页移除对多端能力盘点的影响；断点与分屏能力继续保留。
- 更新模板根 README 的组件清单、目录树、路由页及 Push 说明。

## 错误处理与兼容行为

- 历史 `ScanPage` 快捷参数不再产生导航目标，应用继续进入主页面，不抛出异常。
- 商品深链参数解析失败时沿用当前普通启动行为。
- 删除通知授权后，首页加载不再触发系统通知授权弹窗，也不再发起模拟 Push 网络请求。
- 已安装旧版本产生的隐私确认偏好不再读取，不影响新版本启动。

## 验证策略

新增或扩展 Node 契约测试，至少验证：

- 三个组件目录及 Push 实现文件不存在。
- 构建配置和包依赖不再引用被删除模块。
- `SafePage`、`SplashPage`、扫码路由、扫码快捷入口和 Push 调用不存在。
- `Index` 普通启动直接进入 `MAIN_ENTRY`。
- 商品深链、分屏商品详情和订单快捷入口仍保留。
- 首页不再出现扫码按钮，首页加载不再请求通知授权。
- 通用权限申请接口仍保留。
- 文档已记录本轮删除项和多端适配影响。

完成静态契约测试后，执行完整 Hvigor `assembleApp` 构建，确认 ArkTS 编译、资源合并和打包均成功。

## 风险与控制

- 启动路由改动可能造成空白页：通过契约测试检查 `MAIN_ENTRY` 入栈，并用完整构建验证路由资源。
- 删除扫码逻辑可能误删商品搜索类型：只删除扫码专用的图像入口，保留文本搜索及搜索结果页面。
- 删除通知逻辑可能误伤通用权限工具：只移除 `requestNotificationPermission` 和 NotificationKit import。
- 锁文件残留可能继续解析已删除模块：构建前刷新依赖并对模块名做全工程扫描。
